# Solaris: монитор станций

Каждые 5 минут программа читает Deye Cloud и график ДТЭК (Одесса) и пишет в Telegram.
Работает на серверах GitHub, ноутбук не нужен. Deye Cloud — только чтение, настройки инверторов не меняются.

## Что присылает

| Событие | Сотрудникам | Клиенту |
|---|---|---|
| Свет отключили (по графику или ⚡ вне графика) | да | да |
| Свет включили + сколько не было + заряд АКБ | да | да |
| АКБ села ниже порога, а света нет | да | да |
| За ~30 минут до отключения по графику | да | да |
| График ДТЭК на сегодня / завтра, изменения графика | да | да |
| 🚨 ДТЭК объявил экстренные / аварийные отключения | да | да |
| Станция не на связи / снова на связи | да | нет |
| Отчёт за месяц (1-го числа) | да | да |

Клиент получает сообщения только если у его станции указан `client_chat`.

## Команды в чате сотрудников

Пишутся в группе сотрудников, ответ приходит при следующей проверке (до ~10 минут).

| Команда | Что делает |
|---|---|
| `/stations` | станции, очереди ДТЭК, сколько клиентов подключено |
| `/links` | ссылки-приглашения для клиентов |
| `/queue ПБС 3.1` | указать очередь ДТЭК станции |
| `/title ПБС = Офис на Хуторской` | как называть объект в сообщениях |
| `/reset ПБС` | отключить клиентов станции и выдать новую ссылку |

Клиент открывает ссылку, нажимает Start и начинает получать сообщения по своей станции. Отписаться: `/stop` боту.

## Секреты (Settings → Secrets and variables → Actions → New repository secret)

Вписывает только владелец репозитория. В чат, в код и в файлы их не кладём.

| Имя | Что это |
|---|---|
| `DEYE_APP_ID`, `DEYE_APP_SECRET` | с developer.deyecloud.com → Application |
| `DEYE_EMAIL`, `DEYE_PASSWORD` | вход в Deye Cloud того аккаунта, где станции |
| `DEYE_COMPANY_ID` | только для бизнес-аккаунта, иначе не создавать |
| `TELEGRAM_TOKEN` | токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | чат сотрудников (число) |
| `STATE_KEY` | любая длинная случайная строка — ею шифруется память программы |
| `STATIONS_JSON` | настройки станций, пример ниже (можно добавить позже) |

Пример `STATIONS_JSON` (ключ — название станции как в Deye Cloud или её id):

```json
{
  "Название станции 1": {"queue": "3.1", "client_chat": "-1001234567890", "title": "Офис на Хуторской"},
  "Название станции 2": {"queue": "5.2"}
}
```

- `queue` — очередь ДТЭК объекта (смотреть на сайте ДТЭК по адресу).
- `client_chat` — чат или канал клиента, куда добавлен бот. Не указан — клиент ничего не получает.
- `title` — как называть объект в сообщениях. Не указан — берётся название из Deye Cloud.

## Ручной запуск

Actions → monitor → Run workflow → выбрать режим:
`test` — тестовое сообщение, `diag` — что программа видит по каждой станции (уходит только сотрудникам),
`report` — отчёт за прошлый месяц, `check` — обычная проверка.

## Что важно знать

- GitHub запускает расписание с задержкой 5–15 минут, плюс логгер Deye сам шлёт данные раз в ~5 минут.
  Сообщение «свет отключили» приходит через 5–20 минут после факта. Время в сообщении — время обнаружения.
- «Вне графика» = сети нет, а по графику ДТЭК для очереди объекта свет должен быть.
- График ДТЭК берётся из открытого набора данных `Baskerville42/outage-data-ua` (он читает сайт ДТЭК).
  Если набор перестанет обновляться, отключения по станциям всё равно отслеживаются.
- В журнале GitHub нет названий станций, адресов и данных: только счётчики.
  Память программы (`state.enc`) хранится в репозитории в зашифрованном виде.
